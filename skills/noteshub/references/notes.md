# NotesHub notes (`*.md`)

Plain Markdown files. The file name (without `.md`) is the note title shown in the app, so
name files like titles: `Trip to Kyoto.md`, not `trip_to_kyoto.md` (follow the notebook's
existing style if it differs). Folders are notebook sections. Avoid characters that break on
some platforms: `/ \ : * ? " < > |`.

## What the app renders

GitHub-flavored Markdown (headings, lists, tables, `- [ ]` task lists, `~~strike~~`,
footnotes, autolinks, raw HTML) plus:

- **Line breaks:** a single newline is rendered as a line break. Write each paragraph on one
  line; don't hard-wrap at 80 columns.
- **Callouts:**
  ```markdown
  > [!warning] Optional title
  > Body text.
  ```
  Type is any word (`note`, `tip`, `hint`, `info`, `warning`, `danger`, `example`, `quote`…);
  add `+`/`-` after `]` for an expanded/collapsed foldable callout (`> [!tip]- Details`).
- **Highlight:** `==text==`.
- **Super/subscript:** `^sup^`, `~sub~`.
- **Math:** `$inline$` and `$$ display $$` (LaTeX).
- **Diagrams:** fenced ```` ```mermaid ```` blocks; ABC music notation in ```` ```abc ```` blocks.
- **Code:** fenced blocks with a language for syntax highlighting.
- **Emoji shortcodes:** `:rocket:`.
- **YAML frontmatter** (`---` … `---` at the very top) is supported and preserved; only add it
  if the notebook already uses it.
- **Table of contents** is generated by the app from headings; no marker needed.

## Links, images, attachments

- Link other notes with **relative paths**, URL-encoding spaces:
  `[Kyoto plan](../Travel/Trip%20to%20Kyoto.md)`. Wiki-style `[[links]]` are not supported.
- Embed a whiteboard like an image: `![Architecture](Architecture.excalidraw.svg)`.
- Attachments (images, PDFs…) live in a `.attachments/` folder **next to the note** and are
  named by the SHA-1 hash of their content: `![photo](.attachments/3f0c…e1.jpg)`. To add one:
  compute `sha1sum` of the file, copy it to `<note folder>/.attachments/<sha1>.<ext>` (lowercase
  hex), and reference it with that relative path. NotesHub finds a note's attachments with the
  pattern `(.attachments/<letters-digits>.<ext>)`, so keep that exact form.
- External images by URL work too.

## Editing etiquette

- Preserve the note's structure, heading levels, list style and language. Append to the
  relevant section rather than rewriting; don't reformat untouched parts (keeps git diffs and
  NotesHub's automatic merges clean).
- New notes: a top-level `# Title` is optional (the file name already is the title) — follow
  what sibling notes do.
- Dates in notes: ISO `YYYY-MM-DD` unless the notebook uses another style.

## Merge conflicts

When NotesHub can't merge concurrent edits it writes both versions into the note:

```markdown
:::conflict{variant=a}
some text
:::

:::conflict{variant=d}
altered text
:::
```

The app lets the user pick one. If you see these blocks, show the user both variants and ask
which to keep (or merge them if they ask). Never leave conflict blocks or git markers
(`<<<<<<<`, `=======`, `>>>>>>>`) behind, and never create them.
